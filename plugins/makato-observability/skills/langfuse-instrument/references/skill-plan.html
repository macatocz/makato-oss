Goal Alignment

Does this skill serve the plugin's goal?

Plugin Goal Provide LLM-observability skills for tracing, monitoring, and debugging LangGraph-based AI agents — Langfuse-first via OpenTelemetry SDK + OTLP HTTP export, so LangGraph nodes running without a LangChain wrapper still land structured traces in Langfuse. Vendor-neutral.

How This Skill Serves the Goal

This skill implements the plugin's primary code path: Langfuse-first via OpenTelemetry SDK + OTLP HTTP export. It gathers credentials vendor-neutrally per the § Langfuse deployment stance in AGENTS.md, wires the OTel TracerProvider + OTLPSpanExporter, instruments LangGraph nodes with spans carrying gen_ai.* attributes, ships an in-process exporter for unit-test assertions, and verifies traces on the dashboard. It emits no classic-LangChain CallbackHandler code — matches AGENTS.md Skill Authoring bullet: instrumentation MUST use the OpenTelemetry SDK directly.

Position in Plugin Workflow

First skill in makato-observability. Runs after makato-build ships the agent code and after the consumer has provisioned a Langfuse instance (Cloud, self-hosted, or e2e-local). Complements makato-langgraph which teaches how to author graphs; this skill teaches how to make them observable at runtime through OpenTelemetry telemetry landing in Langfuse.

Workflow

Execution Steps

Step 0 — Gather Langfuse credentials

Use AskUserQuestion to determine deployment path: (1) Langfuse Cloud (US https://cloud.langfuse.com or EU https://eu.cloud.langfuse.com), (2) Self-hosted (any Helm/Docker/Kubernetes URL the consumer supplies), (3) E2E-local (typically docker compose bring-up on http://localhost:3000). Collect LANGFUSE_HOST, LANGFUSE_PUBLIC_KEY (pk-lf-…), LANGFUSE_SECRET_KEY (sk-lf-…). No default endpoint. HALT if operator cannot supply — do not proceed. Load @references/deployment-paths.md.

Step 1 — Confirm agent runs LangGraph on the OTel-SDK path

Read agent entry file(s). Grep for StateGraph, graph.compile(), from langgraph. Confirm the app does NOT use the classic-LangChain wrapper — grep for from langchain.callbacks or langfuse.langchain.CallbackHandler. If a LangChain-callback wiring is present, STOP and point the operator at the plugin scope note: the LangChain-callback bridge is out of scope for this plugin. Load @references/langgraph-otel-integration.md.

Step 2 — Verify OTel and Langfuse dependencies

Check pyproject.toml (or requirements.txt) for opentelemetry-sdk>=1.25, opentelemetry-api>=1.25, and (for the exporter) opentelemetry-exporter-otlp-proto-http. Verify langfuse>=2.0 is present for the verification-side SDK use in tests. Add missing deps to the correct dependency group. Do NOT run pip install; tell the operator to run pip install -e . or uv sync per their local convention.

Step 3 — Wire the OTel TracerProvider + OTLP HTTP exporter

Copy the snippet from templates/otel-setup.py into a bootstrap module (typically the app entry point, before any LangGraph node imports). It: (a) constructs a TracerProvider with a Resource carrying service.name + service.version; (b) attaches an OTLPSpanExporter(endpoint=<LANGFUSE_HOST>/api/public/otel/v1/traces, headers={"authorization": "Basic <b64(pk:sk)>"}) via BatchSpanProcessor; (c) is a no-op when LANGFUSE_PUBLIC_KEY is unset (zero overhead in local dev without Langfuse). Load @references/otel-setup.md for the endpoint-path convention and header format Langfuse expects on the OTLP receiver.

Step 4 — Instrument LangGraph nodes with spans + attributes

For each LangGraph node whose behaviour needs tracing, wrap the node body in with tracer.start_as_current_span(node_name) as span:. Set span attributes from the gen_ai.* and internal-perimeter conventions catalogued in @references/span-attribute-conventions.md. For LLM calls, capture gen_ai.request.model, gen_ai.usage.input_tokens, gen_ai.usage.output_tokens. Honour scrub perimeters: when a node is on a data-sensitive perimeter, set span.set_attribute("input", "[CONTENT SCRUBBED]") and "[OUTPUT SCRUBBED]" instead of raw payloads. The perimeter tag comes from the consumer app's convention — the skill accepts it via context and does not choose it.

Step 5 — Add the in-process exporter for unit tests

Copy templates/otel-inprocess-exporter.py into tests/_helpers/ (or the consumer's test-helpers directory). It: (a) registers an InMemorySpanExporter at session scope; (b) exposes a captured_spans() fixture that returns finished spans for the current test; (c) resets the exporter between tests. Skills MUST NOT hard-code the test directory path — the operator supplies it. Load @references/inprocess-exporter.md.

Step 6 — Configure env vars + verify traces on dashboard (MANDATORY)

Update or create .env.local with the three LANGFUSE_* vars from Step 0. Provide templates/env-local.example as reference. Then start the agent, exercise a LangGraph flow, and verify via REST API: curl -u pk:sk <LANGFUSE_HOST>/api/public/traces?limit=1. Confirm observations > 0 and that gen_ai.* attributes appear. Walk @references/troubleshooting.md on failure. Do NOT declare success until traces are visible on the dashboard.
