# README Style Guide

## Common Mistakes

- **No install steps** - Never assume setup is obvious
- **No examples** - Show, don't just tell
- **Wall of text** - Use headers, tables, lists
- **Stale content** - Add "last reviewed" date
- **Generic tone** - Write for YOUR audience

## NEVER

- **NEVER write from the author's perspective** — you know the project intimately; your reader
  knows nothing; every sentence should answer a question the reader actually has, not one you'd ask
- **NEVER assume OSS format** — internal tools, config folders, and personal projects need
  different sections; always confirm the project type before loading a template
- **NEVER use the project name as the description** — `# my-tool` followed by `A tool for doing
  things` tells the reader nothing; the description must answer what problem it solves and for whom
- **NEVER omit a usage example** — readers skip prose and read code; one concrete command lands
  harder than three paragraphs of description
- **NEVER document future plans as current features** — trust erodes the moment a reader tries
  "coming soon" and finds nothing; only document what works now
- **NEVER open with backstory** — readers want to be unblocked, not educated; lead with what it
  does and how to install it; save motivation and history for later or cut them entirely
