# makato Suite — Feature Verification Audit

> **Audit date:** 2026-08-05
> **Scope:** every feature (skill, agent, script, hook, config) across all 14 makato plugins.
> **Method:** each feature's *expected outcome* (from its `SKILL.md`/`README`/`AGENTS.md` contract) was checked against its *real implementation*, and cross-referenced against actual usage in the [`sagibeast`](https://github.com/macatocz/sagibeast) consumer repo.
> **Corpus:** 158 features across 14 plugins.

This document is the source-of-truth inventory for the makato-suite GitHub Pages site. Each
plugin section lists its features with a status, the gap between promise and reality, and a
concrete fix where one is needed.

| Badge | Meaning |

#### 🟡 partial — `contracts/build-jsonl.md` (config)

- **Expected:** Design-time schema defining required fields, optional fields, step values, examples, and invariants for the append-only build.jsonl event log written by all makato-build skills.
- **Real finding:** The contract documents skill names as 'implement-tdd', 'refine', 'verify', 'push-to-git', 'create-pr', 'address-pr-comments' in the skill field enum description and in the examples. However, all real build.jsonl files in sagibeast use 'build-' prefixed names: build-implement-tdd, build-implement-goal, build-refine, build-verify, build-push-to-git, build-create-pr, build-simplify, build-review. The contract examples are inconsistent with actual production output. The post-implement and pre-push hooks match the real 'build-implement-tdd' / 'build-implement-goal' prefix in their inline scripts, which means the hooks work correctly — but the contract itself is misleading documentation.
- **Gap:** The skill field description and JSON examples in build-jsonl.md use the short form (e.g. 'implement-tdd', 'verify') while every real build.jsonl in sagibeast uses the build- prefixed form (e.g. 'build-implement-tdd', 'build-verify'). A plugin author reading only the contract would write the wrong skill name.
- **Fix:** Update the skill field description and all five JSON example entries in build-jsonl.md to use the build- prefixed names as emitted by the actual skills.
- **sagibeast usage:** All sagibeast specs/*/build.jsonl files contain entries with build-prefixed skill names (build-implement-tdd, build-implement-goal, build-refine, build-verify, build-push-to-git, build-create-pr, build-simplify, build-review, coder, po-agent, progress-comment) — confirming the contract's example skill names are stale.

- **Expected:** Documents a PreToolUse hook that blocks git commit on pre-commit fast-lane failure. Provides a settings.json snippet with blocking: true and timeout: 30000. Also documents SENSOR_HARNESS_DISABLE=1 bypass with audit logging.

The documented snippet requires blocking: true to actually prevent the commit, but the deployed snippet lacks it — meaning the hook runs but does not block on failure. The SENSOR_HARNESS_DISABLE audit log reference describes behavior (appends to 'harness JSONL audit log') but no such log file path is specified and no implementation of that audit is wired in the hook command itself.

The SENSOR_HARNESS_DISABLE bypass audit-log claim is undocumented (no log path, no actual implementation referenced).
- **Fix:** Add 'blocking': true to the PreToolUse git commit hook entry in the sagibeast .claude/settings.json. Remove or qualify the audit-log claim for SENSOR_HARNESS_DISABLE unless the log path and implementation are documented.

## Methodology

- **Enumeration:** every `skills/<name>/`, `agents/*.md`, notable `scripts/`, `hooks/`, `pre-commit/`, and config contract was listed per plugin.
- **Expected vs real:** for each feature, the documented contract (frontmatter + body + README/AGENTS) was read, then the *implementation* (skill body, referenced scripts, shared/ helpers) was inspected for dead references, unwired steps, TODO/aspirational notes, contradictions, and guards that never fire.
- **sagibeast cross-check:** each feature was grepped against the consumer repo's `git log`, `specs/*/build.jsonl`, `workflow-state.json`, `plan-*.md`, `.makato/memory/*.jsonl`, and CHANGELOG for real-world exercise.
- **Orchestration:** 14 parallel plugin evaluators + a completeness critic (makato-build re-run in 3 batches after an initial size-stall).
