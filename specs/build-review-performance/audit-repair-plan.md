# F-001 repair protocol (T5)

## Proposed cutover

Keep `review_scope.fingerprint` unchanged: every changed tracked/untracked byte, source/context/contract path, base and contract version remains protected. The completed final-full certificate (or validated delta checkpoint) is an immutable reviewed-input anchor. Operational audit publication is a separate, narrowly authorized transition, not a new source certificate.

1. At successful `complete` or `checkpoint`, capture the exact full fingerprint manifest, canonical audit prefix length/digest, file mode and physical path identity. Resolve only this story's `build.jsonl` through `spec_folder.resolve_spec_folder` under the bound `evidence_root` (fallback worktree), matching established target-repository audit ownership. Reject symlink components and context/contract physical aliases. An audit outside the worktree remains outside its manifest: bind its identity/prefix without redirecting audit ownership or changing ordinary fingerprint equality. Normalize only a present canonical worktree audit entry. A missing/unresolvable audit leaves ordinary unchanged-tree behavior intact, not an exemption.
2. Add a ledger-owned `publish-audit` operation. It takes no caller fingerprint, path, receipt, arbitrary rows or success boolean. It requires the persisted successful complete/checkpoint certificate and an unchanged live full fingerprint. Generate canonical, minimal schema/privacy-constrained rows from the ledger: final AC verdicts verbatim from its independent final-full pass plus session statistics; checkpoint only a session row, never AC verdicts. Include story, ledger run ID and pass ID. Preserve the existing audit prefix byte-for-byte. Bind a durable publication intent before append, then fsync and persist an audit-transition receipt containing old/new full fingerprints, anchor manifest, exact append bytes/digest, prefix length/digest and canonical path identity. Retry reconciles exactly the intended append; no duplicate row. No source certificate is overwritten.
3. Later `gate`, checkpoint-receipt validation, runtime acceptance and reuse independently verify the persisted receipt against the live full fingerprint and exact appended bytes. Normalize only the single derived canonical audit manifest entry back to its recorded prefix to compare the complete manifests; handle addition to the changed-file set explicitly. No other manifest/path/context/contract byte may differ. Validate the rows against the bound run/pass and ledger-derived schema. Unreceipted tails, prefix rewrites/truncation, extra rows, mixed source edits, mode/path/symlink substitutions and forged receipt fields fail closed. Gates retain the original reviewed input fingerprint for policy/evidence; additionally expose the actual delivery fingerprint and durable transition receipt. Original mechanical no-change evidence remains exact at its original anchor.
4. Runtime accepts fresh/reused success only after that live verification. Completed durable-result reuse must not be mistaken for permission to launch another child; reordering that branch must preserve activation/action/epoch fencing for genuinely new work.
5. Scheduler decision audit occurs before the launch fingerprint: append the decision, then recompute the exact full fingerprint for dispatch. Post-review acceptance verifies a checkpoint receipt at its immutable reviewed anchor and its audit-only delivery transition; persist the anchor snapshot for delta scope. No append is silently treated as source equality. Move any post-review operational audit before receipt publication/acceptance or keep it outside the protected canonical file; no generic audit exemption.
